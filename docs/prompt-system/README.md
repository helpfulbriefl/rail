# BRO v3.0 · система промтов «аналитик + кодер»

Аналитик (сильная модель в чате Notion) думает, решает и принимает работу. Кодер (Zoo Code в VS Code) делает руками. Ты — заказчик: нужен на 4 остановках 🛑 и пишешь пару слов за волну.

Система **ничего не загружает сама**. Она включается, только когда ты вставляешь строку-триггер с путями (TRIGGERS.md). Без этой строки агенты работают как обычно.

## Старт за 3 шага
1. Склонируй систему на ПК (PowerShell):
   ```powershell
   git clone https://github.com/helpfulbriefl/global-promt-system "$env:LOCALAPPDATA\global-promt-system"
   "$env:LOCALAPPDATA\global-promt-system"
   ```
   Вторая команда покажет полный путь — это `<BRO>` в TRIGGERS.md.
2. Дай аналитику доступ к GitHub: docs/GITHUB-SETUP.md (одна ссылка, кнопка Generate).
3. Скопируй строку из TRIGGERS.md в новый чат аналитика. Он ответит «Ходом 0»: что понял, план и вопросы с вариантами по умолчанию.

## Режимы
| Режим | Когда | Обмен |
|---|---|---|
| NEW | проекта ещё нет | через git |
| JOIN | проект уже есть, в том числе на v2.x или по чужим правилам | через git |
| LOCAL | без git | ты переносишь блок задания и zip |

## Одна волна
```text
аналитик кладёт задание в git → ты: новый чат Zoo + «BRO GO …» → кодер делает, проверяет на стенде, пушит отчёт
→ ты аналитику: «BRO CHECK» → аналитик принимает и сразу кладёт следующее задание
```
Первая волна идёт через чат: аналитик даёт блок, ты вставляешь его кодеру вместе со строкой `BRO GO FIRST`.

## Где смотреть прогресс
- карточка в каждом ответе аналитика;
- `.bro/STATUS.md` в репозитории проекта (схема на GitHub);
- `.bro/progress.html` на ПК (открыть двойным щелчком).

## Что где лежит
| Папка | Что внутри |
|---|---|
| core/ | ядро аналитика, CODER-BOOT, грабли |
| modes/ | NEW · JOIN · LOCAL |
| modules/ | разведка, стек и стиль, стенд, метрики |
| templates/ | шаблоны файлов `.bro/` |
| builds/ | готовые START-NEW / JOIN / LOCAL (собирает `tools/bro.ps1 build`) |
| tools/bro.ps1 | все подсчёты, зеркала и сборка |
| auditor/ | промт аудитора версий |
| docs/ | для тебя: WHY, переход с v2.1, GitHub, карточка проекта, старый v2.1 |
| metrics/projects/ | метрики всех проектов для аудитора |

Версия — в файле VERSION, история — в CHANGELOG.md.
