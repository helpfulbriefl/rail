# Почему система устроена так (для Владельца, агенты это не читают)

## Микропромтинг: M1–M6
| № | Правило | Почему |
|---|---|---|
| M1 | Всё, что читают агенты, — на английском, коротко, телеграфом | русский текст стоит примерно на треть больше токенов (G-031), а промт грузится в каждый чат |
| M2 | Всё, что читаешь ты, — по-русски | тебе не нужно переводить в голове |
| M3 | Якоря вместо пересказа: `R8`, `S1–S4`, `D-04`, `G-09`, `M03`, `путь:строка` | ссылка короче пересказа, и её легко найти поиском |
| M4 | Каждое правило записано один раз, в остальных местах на него ссылаются | правила не расходятся между файлами |
| M5 | Модули — по необходимости: ядро всегда, плюс один режим. Стиль — только для интерфейсов, разведка — только в первой волне | агент не читает то, что ему сейчас не нужно |
| M6 | Объяснения «почему» живут здесь | агентам нужны правила, а не их история |

## Ключевые решения
| Что | Почему |
|---|---|
| Аналитик — мозг, кодер — руки | сильная модель дорогая (окно 5 часов и недельный лимит), слабая дешёвая, но выдумывает. Кодеру достаётся только то, где нельзя ошибиться |
| Волны по 3–6 задач одного слоя | микрофиксы съедали окно аналитика (G-020), а большие волны топят слабого кодера |
| 4 остановки и не больше | всё остальное решается по умолчанию с записью в журнал, ты нужен только там, где важен твой вкус или есть риск |
| Аналитик сам пишет в git, но только в `.bro/inbox` и `.bro/exchange` | ты больше не носишь тексты между чатами, а аналитик не может сломать код |
| Не больше 5 обращений к GitHub за волну | каждое обращение — это токены и лимит подключения |
| Нет автозагрузки, только строка-триггер | Zoo сам подгружает `.roo/rules` и `AGENTS.md` (G-027), и система включалась бы там, где ты её не просил |
| Нет доказательств — волна не принята | раньше принимали по словам кодера (G-032), и «готово» оказывалось сырым |
| Аналитик «смотрит» экран текстом | ARIA-снимок и процент отличия от макета — это сотни токенов, а картинку модель может и не увидеть |
| Метрики считают агенты и скрипт, без внешних сервисов | так решил Владелец: только промтинг. Суммы считает `bro.ps1`, потому что модели ошибаются в арифметике (G-030) |
| Никто не ставит оценку себе | модели хвалят свою работу (G-029), поэтому кодер оценивает задание, а аналитик — отчёт |
| Прокси-токены по формуле | модель не видит своих токенов. Для сравнения версий важна не точность, а то, что считаем всегда одинаково |
| Передача дел на 70 % контекста | после этого модель начинает терять детали |
| В новой версии меняем 1–3 вещи и судим после 10 волн | иначе непонятно, какая правка сработала |

## Как читать цифры
- ptok — «примерные токены»: кириллица ÷ 3 плюс остальное ÷ 4. Это нижняя граница, рассуждения модели в неё не входят.
- Вес промта виден в первой строке каждого `builds/START-*.md`.
