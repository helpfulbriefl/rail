## Evidence and corrections

Official https://doc.rust-lang.org/std/fs/fn.rename.html explicitly replaces existing destination files and describes Windows MoveFileExW/fallback semantics. Existence alone does not prove second-save failure. Actual permission/sharing/AV/filesystem errors must be reproduced on the target toolchain/Windows. Never fix by deleting the valid old config first.
- config.rs save ignores serialization/write/rename errors. core.rs has a periodic 300ms coalescing worker, NOT exactly 300ms after the last request; save_now exists but is unused in inspected shutdown paths. Potential dirty-state loss on immediate quit is real. Main quit and tray:quit both exit without an explicit flush. Background write versus flush can contend on one json.tmp and replace newer state with an older snapshot unless serialized. Treat persistence as high priority P1 pending native severity/repro, not proven universal P0.
- sys_top continuity defect is confirmed and already covered by W3B task 3. EXE-basename fallback hazard is confirmed in current tracker/window management and needs extension to existing pinned-item actions, not only new sys_close. Duplicate add_paths invalidates even when all paths already exist; low-risk cleanup with regression proof only.
